# 架构、存储和恢复

## 单一采集链路

`MonitorService` 是用户启用的前台服务。`Engine` 协调实时预览、记录状态、通知面板、两个 WindowManager 悬浮窗和一个常驻 Root 采集进程。页面、双窗和记录共用同一结果，不分别启动硬件读取器。没有实时预览、窗口或未结束记录时关闭采集；通知可继续保留供重新开启，直到用户退出监控。

libsu 只负责 Root 授权与启动。C++ 采集器缓存文件描述符，批量读取硬件节点，通过标准输出传回行协议，避免每周期启动 su、cat 或 dumpsys。硬件采样与逐帧追踪分离；首页硬件预览不为无用的 FPS 启动追踪。窗口最多每 500 ms 刷新，值未变时减少绘制，隐藏窗口不绘制。App 页面离开前台停止预览和图表刷新。

前台应用使用 top-app cgroup 的真实进程与启动器应用目录核对，读取实际包名和 OOM 状态，并以连续样本消抖。排除本应用、桌面和 SystemUI。自动开始只在用户已按开始、处于等待状态时发生。切换应用结束当前记录，通知栏、锁屏和控制面板临时暂停。控制面板使用独立透明 Activity，可点外部或返回关闭，不与完整主界面混淆。

## 记录状态

`idle → armed → preparing → recording ↔ auto_paused/manual_paused → saving → idle`。

开始、停止和保存有状态锁；准备与保存期间小窗重复点击不会创建新记录。结束先封闭有效段，等待有限尾帧后落盘。退出等待准备／保存作业完成，再停止本 App 的追踪子进程和采集器。打开完整主界面视为离开游戏并保存；打开快捷面板保留原会话。

Room 只保存会话、备注、标签、收藏与命名区间等索引。原始硬件与逐帧数据写入 `files/records/<UUID>.wsn`。每秒写一个可校验块并执行文件同步，最后不完整块被忽略，已提交块保留。重开应用后将未结束索引标为意外中断，不自动重新测试。文件系统故障、设备断电和外部冻结造成的可用性不能仅靠一秒同步保证；相关实测状态列在验收报告。

QPT 按采集会话取得使用权，保存原状态；原来关闭才由本 App 开启，最后一个采集需求消失时恢复。原来已开启不擅自关闭。外部状态变化、恢复失败与计数器重置均可见。异常终止留下的所有权日志由下次启动采集器检查恢复。

## 原始块与行协议

每块为大端 `magic:uint32 = 0x57534e31`、`payloadBytes:uint32`、`CRC32:uint32`、UTF-8 payload。单块上限 16 MiB。行类型：

| 类型 | 内容 |
|---|---|
| D | 指标 ID、标签、单位、来源和父域 |
| H | BOOTTIME ns、前台有效标志、充电状态、指标 JSON、来源 JSON、异常原因 JSON |
| F | 呈现时间 ns、帧号、图层稳定散列引用；完整图层名称保存在 layer 事件和帧指标来源中 |
| J | 系统 Jank 时间、分类掩码和来源 |
| E | 事件时间、类型、说明 |
| B / P | 有效段开始／暂停或结束 |

旧版六字段 H 行可以读取，新版第七字段独立保存读取失败／不支持原因。解析损坏或不完整会明确显示质量问题。暂停段、图层变化与采集代次共同划分帧统计，不跨段计算。

## 导入与导出

完整包为 ZIP，只有 `manifest.json` 与 `record.wsn`。包含格式版本、算法版本、SHA-256、设备与应用信息、备注标签及命名区间。导入限制条目白名单、禁止重复条目、总解压 1 GiB、元信息 1 MiB，验证 SHA-256、每块 CRC、时间范围与参数，使用数据库事务写入新 UUID，绝不覆盖现有会话。

当前算法版本为 4，格式仍为 1。版本 2 修正放电统计的峰值范围并增加系统 Jank 原因摘要；版本 3 修正有效结束时间；版本 4 改为记录初段10秒有效帧间隔中位数的自适应慢帧基线，不足校准时计数为 null。Repository 读取完整帧流建立一次基线，即使分析选区也不会改用选区内慢帧重新校准。摘要 JSON 保留基线预算、FPS、观测时长和样本数。缓存键随算法版本更新。算法版本 1–3 的新版记录包仍可导入，以当前算法重算并保留源算法版本；旧 WattScope 的格式不兼容。

CSV 包含 `hardware.csv`、`frames.csv`、`events.csv`、`metrics.csv` 与 `summary.json`。时间列区分 `boottime_ns`、原记录经过时间 `elapsed_seconds` 和剔除暂停的 `effective_elapsed_seconds`；摘要保留统计口径和有效段。硬件长表带单位、完整来源、质量和原因。逐帧表另有 `interval_ms`，段首、暂停、图层变化与采集代次边界留空；事件类型保留实际含义。对比包分别保留 A、B 数据，选同一记录的两个区间时也不共用或覆盖临时文件。

摘要图为独立干净底色 PNG，不自动带入私人背景图片。导出流式读取原始文件，生成唯一文件名，通过 FileProvider 交给系统保存／分享入口。完整分析目前会把一条记录的硬件与帧载入内存，重分析串行执行；长记录详情加载的峰值内存仍需单独评估，不等同于后台记录内存。

图表保留完整分析点列，用时间二分查找提取可见段，再按绘图需求减少点数，保留峰值、端点和缺失段。缩放后重新从完整点列选择，不把第一次总览的稀疏点当作原始数据。真实采样中断与暂停在抽稀前写入空点；指针不跨空点借用旧值。
