# 指标来源与统计口径

内部硬件时间使用 Android 启动以来的 `CLOCK_BOOTTIME` 纳秒。帧事件的单调时钟换算到同一时间域。墙上时间只用于记录日期。暂停段不参与有效时长、帧间隔或能量积分；跨采集重连、图层更换的帧不连接。

## 硬件

| 指标 | 读取与显示 |
|---|---|
| QPT | 从 `/sys/class/powercap/qpt/` 的实际 zone 层级发现名称、父子关系与节点。原始名称和 `debug-*` 保留，不猜测物理归属。 |
| QPT 瞬时功率 | 有效非负 `power_uw / 1e6`，单位 W；缺失时以连续累计能量差分回退。 |
| QPT 能量 | `energy_uj / 1e6`，单位 J。平均功耗优先累计有效能量差除以对应时间，不用瞬时值覆盖能量结果。 |
| CPU 功耗合计 | 本机只合并同级 `cpu-m` 和 `cpu-l`。若未来提供已确认的 CPU 总域，则使用父域一次。不与 SoC 总值、GPU 或 debug 叠加。不是每颗核心或每个进程的瓦数。 |
| 电池侧功率 | 优先有效 `power_now`，否则电流乘电压，按设备单位归一到 W；原始电流、电压、状态和方向仍记录。首页/趋势/悬浮窗按状态显示充电为正、放电为负。记录/分析/CSV：Discharging 保存有效功率绝对值，Charging/Full/Not charging 计 0；未知状态为缺失。 |
| 放电整机统计 | 仅纳入连续 `Discharging` 且有效非负电池功率的区间。充电／旁路不填入此平均值，缺少合格段时显示缺失。 |
| CPU 频率／占用 | 依据 `cpufreq/policy*/related_cpus` 和 `/proc/stat`，区分真实频率簇与每核心。共享策略的逐核频率就是所属簇频率；离线核心明确缺失／离线。占用是调度诊断，不是功耗。 |
| GPU | Qualcomm KGSL 已发现节点；频率单位 MHz，`gpubusy` 按有效窗口 busy/total 计算占用；total=0 为缺失，不回退同窗口百分比来补零；busy=0 且 total>0 保留真实 0%。原始计数保存在来源。标题页零占用不证明 3D 负载已验证，需结合实际场景和原始值。 |
| 温度 | 仅从已确认 CPU／GPU 类型传感器分别取最大值，SoC 取二者较大值。保存具体节点与传感器名称；电池温度独立显示。 |
| RAM | `/proc/meminfo` 的 `MemTotal - MemAvailable`，使用量 GiB／比例 %；不把可回收缓存全部算成不可用。 |
| DDR | 只接受确认含义与单位的实际 DDR devfreq 时钟。带宽投票、memlat、llcc 需求值不冒充 DDR 频率。本机未发现合格来源时显示设备不支持。 |

每项保留数值或 null、最近成功时间、缺失次数／覆盖率，以及正常、暂时缺失、读取失败、设备不支持及原因。合法零值保留。读失败不重复上次值；图表留下断点，不把缺失绘为零。

采样间隔默认 500 ms，可选 100 / 200 / 500 / 1000 ms。功耗相邻样本间隔超过设定值 2.5 倍、计数器倒退／重置、任一端缺失或跨暂停时不积分。能量覆盖时间与完整记录有效时长分别报告，不把局部有效功耗当成全程覆盖。

## 游戏呈现与慢帧

Perfetto 的 `android.surfaceflinger.frametimeline` 和 SurfaceFlinger FrameTracer 注册情况在真机核对。实际逐帧主路径使用 GraphicsFrameEvent 的 `PRESENT_FENCE`，筛选当前应用包名边界及其主 SurfaceView。排除 WattScope 自身、Scene OSD、SystemUI 与其他应用图层。图层重建会保存 layer 事件并重新选择，不连接重建前后帧间隔。

这反映目标图层新缓冲区的呈现间隔，不代表游戏引擎内部逻辑帧或合成器输出总刷新次数。普通 HWUI 应用不保证有 SurfaceView，此时 FPS 显示缺失，硬件记录仍可工作。追踪出错、等待图层和帧中断保留事件与原因，不生成虚拟帧。

对各连续有效段，去重后按呈现时间排序，令相邻间隔为 `d_i` 毫秒：

- 平均 FPS：`1000 × 间隔数 / Σ d_i`。
- 1% / 5% Low：选最慢 `ceil(间隔数 × 比例)` 个间隔，求平均再用 `1000 / 平均间隔`。
- P95 / P99：对有效帧间隔排序，取 nearest-rank 分位数，单位 ms。
- Slow frames：`d_i > 1.5 × 自适应帧预算`；Severe frames：`d_i > 3 × 自适应帧预算`。

算法版本 4 起，每条记录先累计 10 秒有效连续帧间隔，并要求至少 60 个间隔，用其中位数作为正常帧预算，`Baseline FPS = 1000 / 帧预算(ms)`。暂停、图层重建和采集重连的边界不形成间隔，也不增加校准观测时长。偶发长帧参与观测，但不会像平均值那样拉偏基线。基线确定后固定并回算整段；选区和同记录的不同区间沿用该记录的完整基线，不在慢速选区里重新学习“正常帧率”。不足 10 秒或不足 60 个间隔时，FPS/Low/帧时间仍可计算，Slow/Severe counts 为 null，界面显示基线不足，导出也保留 null。

旧 `targetFps` 字段仅为格式兼容而保留，不再控制慢帧阈值，也不修改游戏设置。旧记录会以算法 4 重算并使旧缓存失效。基线来自记录初段，不能推断游戏内的帧率上限设置；若初段是固定低帧率菜单，之后主动改变帧率上限，应重新开始一条记录以重新建立基线。系统 Jank 仍独立采用实际 FrameTimeline 分类，不与 Slow/Severe 混同。

界面指标采用英文名。CPU 详情通过共享 `cpufreq` policy 源匹配核心；CPU freq 用一张图按真实频率簇分别画线，不会因为两颗核心某一时刻频率相同就合并。CPU usage 用另一张图为每个核心单独画线，图例为 CPU 0、CPU 1 等，使用各核心原始占用值，同簇同色，1–2 核簇优先橙/红/紫；旧记录没有逐核占用时才回退到已有总占用。实时详情中的簇占用行仍表示簇内有效在线核心的平均占用，离线/缺失核心不填零。原始逐核数据、来源、数据质量与事件继续保存并可导出，详情末尾不再展示诊断列表。

GPU freq / usage 合并显示：频率使用左轴 MHz，占用使用右轴 0–100%。详情图表固定以 FPS、Frame time、CPU freq、CPU usage、GPU freq / usage、CPU power（cpu-l / cpu-m 两条曲线）、gpu power 开头，然后显示其余可用指标；缺少的指标不生成虚构数据。图表数据线为 0.8 dp，抽稀只影响显示，不影响统计或导出。

图表时间轴使用 `h/m/s`：601 秒显示 `10m1s`，3661 秒显示 `1h1m1s`，47 秒显示 `47s`；区间滑块端点可保留小数秒，CSV 原始时间列仍使用数值秒/纳秒，便于计算。

系统 Jank 只采用匹配已选择游戏主 SurfaceView 的 FrameTimeline 实际 SurfaceFrame 事件，并单独统计，不与慢帧阈值混同。分类按 AOSP 的位掩码显示，组合原因保留在同一行，不将一帧重复计入总数；未知新位保留十六进制名称。[AOSP FrameTimelineEvent 协议](https://android.googlesource.com/platform/external/perfetto/+/master/protos/perfetto/trace/android/frame_timeline_event.proto) 定义了这些分类。当前标题画面的独立追踪没有匹配到目标游戏的该类事件，因此系统 Jank 应显示缺失，不能以零代替“已确认无卡顿”。

详情、选区、命名区间、对比、CSV 与摘要图均调用同一套统计。曲线显示进行抽稀，但统计读取完整原始样本。平均 FPS 对实际观测到的有效连续帧间隔计算；当前尚无独立的 FPS 时间覆盖率字段，结合帧数、断点、事件和记录有效时长判断质量。

## 电池口径与显示（算法 5）

实时首页、趋势和悬浮窗使用实时显示口径，Charging 为正值、Discharging 为负值；Full/Not charging 保留反向后的原始净功率方向。采集器原始电流、电压和状态不改写。

写入记录前将 battery.power 按状态规范化：Discharging 为有效读数绝对值；Charging/Full/Not charging 为策略零值，Unknown 为缺失，放电读取失败不补零。来源中保留原始功率和 `record-discharge-positive-v1` 标记；重复分析/导入不会叠加变换。旧记录只在读取分析/CSV 时套用同一规则，不改写原始块文件。

统计版本 5 使缓存失效并重算；平均放电功耗、能量和峰值仍只采用连续有效 Discharging 段，跨充电切换不积分。全程充电的记录曲线/CSV 为 0，但“放电平均功耗”无有效放电区间时显示缺失。SoC/GPU/CPU 等其他功耗继续独立记录。

详情 CPU pwr 为 cpu-m 与 cpu-l 分项平均功耗的算术和；任一分项没有有效平均值时缺失，沿用各分项有效覆盖时间。CPU 合图仍分别展示原分项，不生成总功耗采样曲线。SoC/Battery 图可选择其他 W 指标叠加；曲线不相加，选择按图表类型保存。

图表可见范围统一由详情顶部双端区间滑块控制，松手自动重算选区摘要；命名区间可保存、重选和对比。点击或横向滑动图表可同步查看时刻和每条曲线的原始最近样本，保留真实零和缺失断点；不使用显示抽稀后的点代替原始值。该操作只移动查看指针，不更改区间或统计。图表不提供平移/缩放及指针/平移模式按钮，纵向滚动浏览保留。
